## 教学怎样推进

代码先把基座走通，讲解仍按章节顺序。每章依次理解问题、Pi 源码过程、组件与数据流、自己的实现，再执行 README 的验证。能说明输入、输出、状态变化和失败路径，再进入下一章；如果理解卡住，就缩小例子，不继续堆功能。

当前用户正在复核 s03。先补本次输入的简单用量累计，再继续 s04 事件、s05 流式，随后讲 s06 的消息所有权与落盘。已经定位的 thinking 兼容、s04 失败历史及依赖加载边界分别按受影响章节回补，不把后续完整能力搬进旧章。

用量验收随功能推进：s03 累计本次输入触发的全部请求；s04 事件保留最终 usage；s05 不重复累计流式快照；s06 保存/恢复后的会话统计一致；s09 命令查询。缓存、可靠费用与当前上下文占用分别在模型适配和交互专题增加，编号待定；不能把累计消耗当作上下文占用。

讲到 s08–s12 时修订输入来源、命令冲突/异常和用户排队输入的 Hook/资源处理路径。每章只讲新增机制与必要修正，不重新包装一次 SDK。具体复现和验收见复核文档 A01–A06；当前这些问题尚未修复。

## 后续专题（编号待定）

先讨论并确认教学范围，再依赖现有接口逐项落实：

1. 实际编程工具：依次完成写文件、精确编辑、进程执行及搜索，先跑通“读取→修改→测试”。工具进度、结构化结果、系统提示组装随实际工具需要加入；手工 shell 在共用执行器上落实 `!`/`!!` 和历史投影，不与扩展 /命令混为一谈。
2. 模型能力与会话演进：模型/推理设置、来源元数据、配置优先级、会话格式迁移与不完整工具历史修复，为切换模型、上下文预算和会话树提供依据。SDK 与 CLI 同期接入，不另开 SDK 章节。
3. 运行恢复、树与压缩：区分 SDK 请求重试、会话层退避重试和上下文溢出；再落实分支上下文重建、预算触发、摘要失败/取消与队列恢复。完整日志保留，已执行工具不因恢复而自动重跑，摘要消耗进入统计。
4. 扩展实践与必要交互：用 Hook/命令/状态实现审批、Todo、命令历史策略等；按实践需要补确认/输入、运行期间投递、取消后继续、诊断通知及资源扩展接口。避免在核心硬编码特定工作流。
5. 完整 TUI、资源包/信任设置、并行工具、多模态、更多供应商、JSON/RPC 等按实际用途逐项安排。MCP、子 Agent、plan mode 等若实现，作为扩展能力，不冒称 Pi 内置核心要求。
