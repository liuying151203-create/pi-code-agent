## 教学怎样推进

教学严格按章节顺序进行，已完成的产品基座随教学逐章核对。每章依次理解问题、Pi 源码过程、组件与数据流、自己的实现，再执行 README 的验证。能说明输入、输出、状态变化和失败路径，再进入下一章；如果理解卡住，就缩小例子，不继续堆功能。

当前已学到 s06 的会话与落盘。编号迁移已完成，s07 手动压缩与恢复已接入；接下来按 [上下文压缩设计](context-compaction-design.md) 在 s07 分阶段实现和学习手动压缩、自动压缩与溢出恢复；随后按顺序学习新 s08–s13 扩展基座，s09 Hook 章节同时接入压缩扩展。后续快照需逐章在新前一章基础上接续，不能只改编号就宣称已有压缩。

用量验收随功能推进：s03 已累计本次输入触发的全部请求；s04 事件保留最终 usage；s05 不重复累计流式快照。会话累计、缓存归一化与当前上下文占用在 s07 第二阶段随自动压缩实现，s10 命令修订时提供查询；可靠费用仍按模型能力专题安排，编号待定。不能把累计消耗当作上下文占用。

讲到新 s09–s13 时修订输入来源、命令冲突/异常和用户排队输入的 Hook/资源处理路径。每章只讲新增机制与必要修正，不重新包装一次 SDK。具体复现和验收见复核文档；A01–A03 已修复，A04–A06 尚未修复。

## 后续专题（编号待定）

先讨论并确认教学范围，再依赖现有接口逐项落实：

1. 实际编程工具：依次完成写文件、精确编辑、进程执行及搜索，先跑通“读取→修改→测试”。工具进度、结构化结果、系统提示组装随实际工具需要加入；手工 shell 在共用执行器上落实 `!`/`!!` 和历史投影，不与扩展 /命令混为一谈。
2. 模型能力与会话演进：模型/推理设置、来源元数据、配置优先级、会话格式迁移与不完整工具历史修复，为切换模型、上下文预算和会话树提供依据。SDK 与 CLI 同期接入，不另开 SDK 章节。
3. 会话树与分支：在 s07 压缩和 s09 压缩 Hook 基础上落实分支路径重建、分支摘要及树导航；会话层普通网络重试与上下文溢出恢复分别设计。完整日志保留，已执行工具不因恢复而自动重跑，摘要消耗进入统计。
4. 扩展实践与必要交互：用 Hook/命令/状态实现审批、Todo、命令历史策略等；按实践需要补确认/输入、运行期间投递、取消后继续、诊断通知及资源扩展接口。避免在核心硬编码特定工作流。
5. 完整 TUI、资源包/信任设置、并行工具、多模态、更多供应商、JSON/RPC 等按实际用途逐项安排。MCP、子 Agent、plan mode 等若实现，作为扩展能力，不冒称 Pi 内置核心要求。

以上每个主题均须在开工前细分成只增加一个核心机制的小阶段，并按 [复核文档](pi-alignment-review.md) 的依赖和验收落地；s07 压缩及 s09 扩展 Hook 的范围、接口、兼容和测试见 [压缩设计](context-compaction-design.md)，目前手动压缩已实现，自动压缩和溢出恢复尚未实现。

资源加载暂未实现完整 ignore 文件、包管理资源与 worktree 遮蔽；多模态及供应商专属 Hook 也没有宣称完成。具体暂缓项留在对应 README，本轮不把它们混入扩展基座验收。
